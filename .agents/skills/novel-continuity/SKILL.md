# 续写与连续性核对

## 按请求选择交付

| 请求 | 执行与交付 |
|---|---|
| 查前情、查一个事实 | 定位用户问的章段，查到足以回答就给结论和出处。若证据只支持某一步，说明能确认到哪一步。 |
| 查穿帮、检查衔接 | 对照前后章段。只报告影响理解的差异，给出两处依据、影响和最小修改建议。可由正文解释的跳时、转场或同一动作的回接可以直接说明为连贯。 |
| 续写、接写指定稿 | 按指定视角和起点交付候选正文，完成后回查相关事实和信息揭示顺序。已有下一章时，只有比较、接写现稿或改写才读取该稿。 |

按[仓库入口的交付规则](../../../AGENTS.md#交付规则)交付。

## 定位版本与故事进度

1. **选正文。** 按[仓库入口](../../../AGENTS.md#选稿件来源)选择来源。使用仓库稿件时，按[作品导航](../../../project/AGENTS.md)定位相邻章节和处理异文。拆书资料、细纲和状态卡可用来定位，影响结论的事实回到正文核实。
2. **定起点。** “接着这段”以指定段末为边界；“接上一章”以所选正文的章末为边界。按实际卷章顺序找上一篇，章号重置时用卷名区别。核对跨卷承接时连读上卷收尾和下卷开场。缺状态卡时直接从正文恢复状态。
3. **按时点取证。** 查前情和续写以目标时点已发生的事为依据。区分读者已看到的线索、视角人物亲历或听说的内容、以及其推断。用户要求查全书伏笔或核对前后时可以读后文，引用时写清揭晓或回收实际发生在哪一章。
4. **只核对相关状态。** 从当前场景需要的时间、地点、在场者、资源和未结事项入手。将消息、计划、承诺和结果逐一对齐，如接单、完成、到账。数字或位置变了，沿中间正文找交易、耗用或移动依据；找不到时标明已查范围。

## 续写完成后

- 通读开头与前文的接缝，核对视角、角色称谓、邻章语气和上一动作的结果。检查新状态有本段行动支撑，伏笔与秘密按人物知情范围推进。
- 用户要求章末状态卡时，记录本章实际变化和仍待兑现的事项，附对应章段。用户要求出处或核对说明时，将它们放在候选正文外。
- 证据写到文件名、卷／章题和可定位的行号或短引文。多个版本各用自己的位置。
- 在桌面书库中按[本机智能体接口](../../../docs/AGENT-INTERFACE.md)读取已授权作品。先定位目标章和相关前文，涉及固定依据的写作任务时使用对应冻结包。
