# 墨卷：安全改稿与历史阶段

## 范围与状态
基线为用户重新附加源码 ZIP 中的 `2eda5b54d2e5aa1c7fa3ac0a75ee436f7f329d21`。
本阶段交付源码，不是经过 Windows 验收的安装包。仅在云环境用隔离数据开发和测试，没有打开用户真实书库、调用外部模型、上传稿件或推送仓库。

已实现：统一 Service 单写入锁、GUI 自动保存历史、不可变提案、版本冲突/幂等、待采纳前后对比、人工确认、历史恢复新版本、整库恢复 epoch 失效、CLI/受限 MCP 协议与 Linux 本地 IPC 源码。

尚未完成的端到端路径：Windows 桌面连接授权界面和安全命名管道未启用；Linux host 提供人工终端授权但实际 socket bind 被云运行环境 EPERM 拒绝，因此真实 CLI↔host 联通未验收。不能把协议单元测试描述成“智能体已经可以连接这台 Windows 软件”。

## 信任与一致性
- `Service` 持有文件系统 writer 锁，编辑器和 host 同库不能同时开启写入。连接检查与请求执行使用同一 Service 互斥锁。直接自行写 SQLite 的同用户程序不在防御范围内。
- 正文保存通过 expected_revision 条件更新，在一个 SQLite 事务内记录正文、revision、历史及审计。失败全部回滚。
- 智能体没有采纳、删除、历史恢复、备份恢复、任意文件、SQL 或 Shell 工具，只能读取一本授权书和提交/查询/取消自己的提案。
- 自报客户端名不等于身份验证。会话绑定随机连接身份；断线、撤销、超时或恢复全库后失效。协议错误后连接永久关闭，不重连、不重放。
- 幂等键作用域为当前连接身份：同键同内容返回原提案；同键不同内容拒绝。重连不会继承身份；永久删除章节或整库恢复会删除相应提案记录及幂等键。
- 提案采纳必须同时匹配提案基准版本和操作预期版本。拒绝旧提案不依赖正文版本，不会更改正文。回滚是创建新版本，不逆向覆盖历史。
- 界面采纳确认绑定具体提案和版本，历史确认绑定具体章节/历史版本。异步过期结果不会替换当前确认目标。离开编辑/打开面板前先保存，失败时保留草稿。

## 容量约束与未解决项
- 每章 pending 最多20，总 pending 最多100；所有状态提案共最多1000，原文加建议稿合计32MiB。拒绝或取消不释放总量配额；不会自动永久清理。到限只阻止新提案，手写保存不受提案配额影响。本阶段尚无提案归档管理界面。
- 每次正文保存保留完整快照，没有压缩、差量存储或自动删除策略。长期高频编辑会增加磁盘使用，这是未完成的容量优化。
- JSON v7 备份含历史、历史名称、资料和回收站，兼容恢复v1-v6，不携带授权会话、提案或审计；64MiB限额保留。历史过多时 JSON 导出会明确失败，不删除内容，不应通过删正式稿件尝试解决。
- GUI 的前后对比为逐栏完整文本，不是逐行差异高亮。
- 浏览器预览只使用虚构内存数据。生产网页不会用 localStorage 冒充数据库。
- Windows EXE、原生窗口/输入法/文件对话框、升级卸载行为、真实 IPC 仍待对应环境验收。

接口和验收命令见 [AGENT-INTERFACE.md](AGENT-INTERFACE.md)，完整当前验证记录见 [VERIFICATION.md](VERIFICATION.md)。

## 恢复前的一致性留底
恢复 JSON 或受支持 SQLite 之前会通过 SQLite 官方 backup API 分页复制当前完整数据库，在独立文件执行完整性、外键及必要表结构校验，关闭并同步后才以不可覆盖方式发布 `.sqlite` 快照。复制/校验/发布任何一步失败，均不继续替换书库。原目标文件绝不覆盖；失败仅清理本次自建临时文件。

这份快照含正文、回收站、历史、提案和审计，不受 JSON 的64MiB或普通SQLite导出的512MiB限额影响，也不静默删除旧历史。现在可通过图形化面板校验和恢复当前已知结构的SQLite独立备份，正式导入仅复制规范数据，不还原运行任务、提案、旧审计或授权。Windows文件系统发布行为仍待原生验收。

外部SQLite只读打开，限制SQL资源并拒绝触发器、视图、虚表、陌生结构和非空WAL；只复制固定列到私有可信候选，不执行外部schema，不覆盖实时数据库文件。确认绑定单次随机令牌、10分钟期限、当前epoch和写入计数；随后使用同一Service锁完成已验证留底及事务导入。512MiB源文件/规范文本上限，树与历史各100000项，单篇10MiB，元数据32MiB，资料字段总计32MiB，已有单卡/单书限制仍有效。JSON导入版本1至7，64MiB限制保留。

取消/错误会回滚未提交操作并清理本次候选；若留底已发布则保留以防丢失。运行重启不自动继续恢复。系统调用可能延迟取消，SQL执行有120秒时限，不承诺硬实时响应。不要运行时手工替换library.db或删除唯一备份。全库当前正文仍由既有界面一次加载，不能把有界备份实现视作整个编辑器无限容量支持。

## 分页历史浏览与名称
GUI仅历史标签页加载metadata索引，点击单版本按需读正文；名称独立CAS与epoch校验，清空名称保留计数防旧请求写入。名称不会创建正文快照。分页使用覆盖索引和revision范围游标，筛选或书库恢复后旧游标不能混用。正式恢复只开放scoped/epoch桌面入口，旧无scope核心方法仅内部兼容，不注册到桌面或外部智能体。

## 正文批量替换
桌面编辑器可建立单个进程内可信候选，按当前作品完整活动章节清单和epoch校验，BEGIN IMMEDIATE内一次提交所有save_in_transaction。保留正文历史与审计，关联资料依已有revision判定自然变为待复核。不新增数据库表或备份版本；候选不进入备份、不跨重启持久化、不开放给Broker/CLI/MCP。

候选详情按章读取；列表仅有限片段。替换后长度用checked算术预计算，先限额再分配。UI进入前flush，确认绑定冻结参数，迟到预览/详情不回写新输入；成功提交与后续加载分开，未知结果要求核对而非自动重发。本阶段没有正则、选择性勾选命中、整批撤销或后台可取消扫描。原生Windows交互仍未验证。

## TXT新作品导入
有界文件读取与纯字节解析分离，冻结源仅在本进程候选中，不保存源路径或运行指令。模式可在选文件前指定，识别超限可以单章模式重新选择（仍受10MiB单章约束）。修改配置基于冻结源而非重新读取；成功返回新ID，失败标记not_ready，旧配置不可提交但可重新配置。详情按章读取，候选只占有界内存。

确认在Immediate事务内重新检查epoch、树与历史预算，再用新UUID插入书/卷/章及revision0历史和审计。没有用整库write替换旧状态；任意失败回滚。导入不新增schema或备份版本，CLI/MCP不可调用。Windows原生文件选择及桌面接线仍只有源码，未验证运行。

## 定向TXT导出阶段
新增仅受信桌面入口 prepare/save/discard 导出，未开放外部agent方法。Service在一致读事务内查询所选作品活动树，按sort_order,id排序，逐章生成32MiB内冻结字节；单章10MiB读取前SQL检查，100000节点上限，10分钟一次性候选，4000字符预览与最终字节同源。导出选项不改变存储正文、数据库schema或备份版本。App优先使用txtExport，旧exportBook仅保留兼容。Windows桌面cfg尚未验证。

## 安全拆章阶段
新增仅受信桌面prepare/detail/commit/discard拆章操作。原始UTF16光标按Unicode scalar校验，UI映射textarea标准化换行坐标回原文，拒绝代理对/CRLF中间。候选捕获epoch、原章正文/版本和卷内活动目录manifest，Immediate事务重新校验再保存前半/新建后半/历史/审计/目录。保留旧关联于原章且不复制，原章source/payoff状态随revision变更为stale，旧提案采纳冲突。无新数据库schema、备份版本或外部agent路由。Windows桌面仍未编译运行。

## 资料内容历史阶段
资料新增content_review_required及material_content_versions。共有写入服务保留标题/fields历史，恢复仅内容且强制待复核；明确复核动作校验epoch、当前资料revision及source/payoff当前版本。普通保存/agent建议不能清flag，agent读取可见，context检查包括无来源但待复核卡。历史读写/复核没有外部agent路由。
JSON格式8及SQLite canonical表白名单/暂存/验证/计数/恢复保留历史与flag，旧数据补当前baseline。100000条/256MiB历史额度，不自动清理。历史是正式数据，不按提案/任务清除。Windows未验证。

## 固定约束写作阶段
作者在已有章节配置必需资料并生成冻结包；严格提案通过已授权Broker，显式引用和自报冲突，人工审阅采纳。Service旧提交/旧批准两入口守卫，active/paused不可绕过，配置变更取消待审。目标/资料实际内容metadata及source/payoff链在提交和采纳重核，待复核卡不可用作硬依据。
JSON9/SQLite保留三类正式配置/依据/严格审核证据；恢复授权不复活，epoch旋转、旧严格建议live_epoch清空、active配置暂停。替换现有active/paused配置需显式确认，legacy恢复入口默认拒绝。包/提案64MiB预算、单包4MiB与30分钟、分页/分块限制，不自动清理。语义正确不作保证。

## 逐项作者审阅阶段
受信桌面调用 `save_constrained_review` 保存对冻结包内每份必需资料的判断（未审阅、符合、有疑问、有冲突）及可选备注。首次 expectedRevision 为 null，后续传最新读取的 revision。只保存最新判断和单调版本，不保留每次草稿历史。严格批准必须调用 `accept_reviewed_constrained_proposal`，携带所见审阅版本；旧的 decide 入口只允许拒绝。已保存的所有必需项明确符合且原有自报冲突单独确认后，正文、历史及证据同一事务提交。判断由作者提供，不是自动语义判定。

JSON/MCP 不暴露作者审阅的写入、批准或备注读取。外部严格提案的提交、幂等重放、读取和撤回仍使用同一有界回执，不含正文或作者审阅字段。JSON10 兼容读取 1..9，SQLite 的提案载荷无新增表/列；备份保存历史审阅但恢复后不重新授权。每项备注4096 UTF-8字节、整份编码64KiB，并计入原64MiB写作证据预算。
