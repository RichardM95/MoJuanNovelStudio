### 同一原创单章：章节历史返工（非整库恢复）

原真实 MCP/管道采纳与备份恢复不变。这段从已经验证的生产 v2 SQLite 导出建立隔离副本，检查原 epoch、正文、历史 ID、审计、冻结包及完整决定，再沿此 v2 分支继续；不是在换过 epoch 的恢复后主库上续写。章节恢复、作者评审及实际导出走生产 Service，新建议由另一个**进程内**生产 Broker 会话提交固定虚构文本，不新增真实管道/网络/socket 路径。

| 检查 | 可复验证据 |
|---|---|
| v2 待决、错误输入与原子性 | 实际冻结 v2 并创建一份待决建议，可信作者逐卡审阅但不采纳。过期正文 CAS 和同书错章历史 ID 分别拒绝；只在正文和历史都已写入事务后、最后插入审计时触发隔离 SQL 失败。每次复读完整 v2、历史与审计、原采纳/拒绝回执、v2 待决审阅与 epoch 均无变化。 |
| v3 → v4：正文相同、版本不同 | 用原 v1 历史 ID 恢复为 v3，再以采纳 v2 历史 ID 恢复为 v4；历史、来源、审计追加而非改写，epoch 不变。v4 正文逐字节等于 v2，包含 CRLF 与 🌙；新键不能用 v2 包提交，v2 待决建议即使已有作者审阅也不能采纳。原 v2 的采纳回执仍是 `accepted_revision=2`，旧包和待决审阅保留，不以归档或清除换取拒绝。 |
| v5 新决定、重开与实物 TXT | v4 重新冻结后提交新建议，未逐卡审阅不能采纳，作者审阅并决定才到 v5。完整 v0–v5 历史的唯一 ID、来源、字节、审计、保留的旧回执及新 v5 回执经实际关闭重开复读。真实单章 TXT 为 184 字节（UTF-8 BOM、CRLF、不含标题或元数据），候选仅消费一次，同名文件不覆盖。 |
| 实际 App / 模拟桥 | 同样的原创片段从作者采纳后的界面打开历史，查看 v1/v2 原文、取消零写入，再确认按书/章/选定历史 ID/当前修订/epoch 恢复，编辑器更新且 v2 历史仍可读。另一次在 v2 有作者草稿时，打开历史必须先保存；失败或保存仍在等待时，不能进入历史或发出恢复，未保存稿保留在编辑器，成功保存后才可访问历史。桥接响应及文件系统未联调，DOM textarea 的换行归一化不算磁盘证据。 |

### TXT 导入和导出的字节上限不是同一个值

用真实写入、非稀疏的合成中文文件验收。**导入最多 16 MiB（16,777,216 字节）**，BOM、卷章标题和行尾都计入源文件大小；每章正文另受 10 MiB 限制。双卷各约 8 MiB 的测试文件在门槛上可读取、预览、提交并核对全部正文。追加一个有效 ASCII 字节（不是损坏 UTF-8）后，选文件读取和直接调用服务各自拒绝；后者使旧导入候选失效，重开书库也未出现新书或正文改变。

**导出最多 32 MiB（33,554,432 字节）**，按导出选项生成的 BOM、标题、CRLF 和分隔均计入；单章正文同样须不超过 10 MiB。两卷四章通过正常编辑保存，生成恰好 32 MiB 的全书输出。预览只显示去 BOM 后的前 4,000 个 Unicode 标量；取出完整候选后写盘并按独立预期逐字节核对，同名写入不会覆盖已有文件。失败后旧票已消耗，另存要重新生成预览。在 SQLite 里给尾章另存一个有效字节（不改已导出的文件）后，服务在生成整书候选时拒绝，旧候选不可再用，已有文件和书库保持不变；改单章仍可导出；同一份更新后的四章仅改为 LF、不加 BOM，也可完整导出，实际为 33,554,406 字节。这不是断电或磁盘故障验收。
