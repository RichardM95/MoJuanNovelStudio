# 冻结前文位置核对

现有前文选择目录仅含目标之前的章节，缺失 ID 不能证明移到后方。复用全书伏笔目录会有最多 16 MiB 同步读开销，也无法把范围绑定到已冻结依赖。因此选择一个作者侧按需元数据查询：只接受书、目标、包、epoch，在同一 SQLite 读取边界校验冻结包并检查其确切前文 ID（至多 8 项）。用现有目录排序比较，分为之前、之后、当前不可见；归属错误、目标不存在或无可信结果不猜原因。不显示当前章正文；校验旧包仍需按既有 4 MiB 上限读取其载荷。复用异步工作线程与不等待的书库锁，不扩智能体 API。

只对当前建议提供核对；响应须与当前书库、章、包、建议和冻结 ID 一致。关闭、切换、重试或旧 epoch 不接受晚到。只报告查询时目录位置，不推断故事内时间；已证实位于目标之后才额外拦旧保存和采纳，未知仍由既有服务端门槛处理。到前文选择区只移动焦点，沿用现有手工保存/冻结流程和未保存备注保护，不自动修改依赖或审阅。
