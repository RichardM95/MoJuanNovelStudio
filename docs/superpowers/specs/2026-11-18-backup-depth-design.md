# 备份取消竞态与采纳稿恢复验收

用户已授权按新版方案持续深入，Windows 暂停，不增加模型或外发稿件。基线 49346b7 / Library v7。

## 因果与选择
已复现 BackupPanel 在用户立即取消后，旧渲染的 passive polling effect 递增共享 generation，丢弃有效取消响应。未修改原组件定向调度 3/3 失败；隔离副本增加同步 acting 锁检查后 60/60 通过。历史那次超时没有 trace，不能断言必为此根因或排除全部不稳定。
选择最小同步互斥入口防护，保留既有 generation 对旧轮询的失效保护。不选择提高超时、删除 generation 或重构整个作业状态机。正常轮询、状态读取、提交、终态与不确定结果规则保持。

## 验收
正式回归必须在原实现失败，修复后通过，包含按钮刚出现即点击、迟到轮询、取消迟回/重复操作、不确定失败不能自动重发。按真实返回区分请求取消与已取消。仅 JSDOM 自动化，不称原生时序已验。

随后复用原创单章验收的实际 v2 采纳结果，用现有 BackupJobManager 导出 SQLite，再保存独有 v3、正式确认恢复 v2。核对决定/审阅/引用保留且归档、策略暂停、epoch 与授权失效、旧决定不能重发、真实关闭重开、TXT 字节一致。读取恢复前快照必须见 v3 并可通过正式恢复准备校验，不只检查文件存在。按现有后台测试方式覆盖失败或取消无半写；不得新增测试专用生产接口或绕过写者锁。

不扩大原创文学样本，不宣称语义正确、生产 socket、原生 IPC、物理故障耐久性或 Windows 已验。保留所有失败证据，独立任务与最终审查、全量回归后替换同一 Library。
