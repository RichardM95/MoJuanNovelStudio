# Crash/relaunch chapter draft recovery — backend contract

## Scope and safety

Trusted desktop only. Checkpoints are separate from canonical chapters, normal version history, agent tools and manuscript exports/SQLite/JSON backups. Persist checkpoint operations in a bounded SQLite sidecar next to the canonical database under the existing single-writer Service lock. Do not create the sidecar during ordinary library open, restore, staging, CLI/agent work or recovery reads if there is no sidecar. `:memory:` Services do not offer durable checkpoints. A client may inspect or load a candidate into an editor; these commands cannot save canonical prose or automatically rebase stale text.

## API

- `start_draft_recovery_session()` returns `{session_id, epoch}` and revokes earlier in-process writer leases. A restore changes canonical epoch, invalidating old leases automatically; old-database records do not cross epochs even when every ID is reused.
- `read_recovery_draft(scope)` accepts exact `{epoch, book_id, chapter_id}` and returns that same scope, `current_revision`, `current_body` and `record` (null or `{token,base_revision,base_body,draft_body,state}`). Current ancestry must be active and in the exact requested book; wrong epoch or scope never returns prose. `matches_base` requires exact canonical revision and raw UTF-8 body. `already_saved` requires either an unchanged exact base/draft or exactly `base_revision + 1` and canonical raw body equal to the submitted draft. Other same-epoch changes are `stale`, read/copy only, never an overwrite/rebase decision.
- `checkpoint_recovery_draft(input)` adds `{session_id, stream_id, sequence, expected_token, base_revision, base_body, draft_body}` to scope, returning `{token,state}`. Sequence increases per active writer lease and is compared against the stored scope watermark. Same lease+editor stream may advance a candidate. A different stream cannot overwrite an unresolved copy unless the caller explicitly adopts the current exact `matches_base` record with its token. Already-saved rows and author-dismissed rows can start a fresh stream. A supplied token is an exact CAS, not a hint. The request base must match live raw bytes/revision or the exact raw body of an older persisted canonical history row for this same active chapter. Thus B typed while A saves remains copyable even when A commits but its reply is lost. Missing or fabricated history is refused.
- `dismiss_recovery_draft(input)` accepts the scope plus `{session_id,sequence,token}`. It soft-hides only the exact latest token; the monotonic barrier prevents an older pending checkpoint restaging it. No background or read-side permanent deletion, expiry or auto-dismissal. A subsequent explicitly scoped newer checkpoint may replace the retired slot. No stale ack/cleanup can erase a newer copy.

The sidecar caps one latest slot per epoch/book/chapter, 1,024 total slots (including archived/dismissed slots) and a 64 MiB logical total of base/draft UTF-8 bytes, 10 MiB per body. Logical limits are not a measure of file overhead or system free space. Quota, stale lease/sequence, scope/anchor mismatch and storage failure are explicit; no silent eviction, relabeling, merge, transfer or automatic reassignment. Archived records are retained locally but not shown in reused scopes by these commands. This feature is not a backfill for content that was never checkpointed, a new archive UI, or a physical power-loss guarantee.
