# 稿件内嵌指令样文本：协议授权验收

基线fa9cb11 / Library v9。用户要求稿件文本不能变成授权指令。只读核查发现已有跨书/作者方法/参数严格性测试，但没有将带指令样正文读回与上述拒绝贯通。

采用独立虚构真实MCP子进程场景，不改变产品。正文含CRLF、emoji、伪系统标签与JSON样跨书读取/自行采纳要求。生产Service保存，真实pipe读取正文及冻结包中正文，逐字符串核对原样保留。随后测试客户端显式发出越权请求，不是模型被诱导执行：另一书章节/资料/包、授权方法、作者采纳方法、伪造作者审阅字段必须依实际协议拒绝，响应不泄露另一书秘密标记。合法严格建议为正例仅进入待审，不能靠文本或字段升级为采纳。子进程退出后真实重开SQLite，两书正文/版本/历史和建议决定不被越权改变。

此路径只证明服务端权限/协议边界，不证明未连接模型抵抗提示注入，也不过滤或修改稿件。采用独立fixture避免污染原有原创文学样本。云端隔离数据，无Windows/用户电脑/网络稿件发送，无新协议/模式/依赖。独立审查、全量回归、同一Library更新，保留证据。
