# 前文章节冻结上下文

基于 d9b5ae8；用户委托自主选择下一完整优化阶段。仍是 Rust/React/SQLite，云端实施，不接模型、不外发稿件、不验证 Windows。

## 取舍
A仅让智能体另读现有章节，不绑定版本，作者采纳时不知道前文变化。B作者显式选择前文，全文冻结并纳入依赖重核，选B。C自动全书召回/总结及模型续写需要新语义能力与传输选择，本阶段不做。

## 范围与数据
每个章节写作配置可附0..8个同书活动前文章节ID，排除目标章和后文。顺序按实际目录稳定键(volume.sort_order,volume.id,chapter.sort_order,chapter.id)，不是按标题数字猜测。保存配置校验ID唯一、有效且严格早于目标；暂停/停用仍可在引用删除时操作，作者也能从界面明确移除失效引用。

新增配置 context_chapter_ids，旧配置缺省空。生成新包时冻结各选中章完整 Chapter 和父 Volume，包含正文/标题/revision/顺序；每章最多1MiB，整个包保持4MiB编码上限，既有64MiB总证据预算不变，绝不静默截断。先校验长度再读正文，按ID读取而非数据库正文排序。仅作者配置/生成；agent不能自行选择、扩大上下文。

新包handle_version=3，目标chapter:<id>、资料material:<id>保持，前文context:<id>独立命名空间。manifest标明context_chapter类型、原始chapter ID及目录位置、字段body/$title；已有分块读取最多32KiB原始UTF8，允许合法引用到前文字符范围。全体必需资料引用覆盖仍强制，前文是补充叙事上下文，不新增强制引用覆盖；不把引用当语义证明。智能体自报冲突的entry_ids仍仅指必需资料原始ID，说明字段可描述衔接疑问，本阶段不变更该协议。

从旧Service configure调用必须保留已有前文集合，不能因旧API不传新字段悄悄清空。新可信configure_with_context接受明确集合并沿用CAS/epoch，修改同事务取消旧待审。新UI始终明确发送集合。新上下文身份与内容在提交提案、保存作者审阅、最终采纳各路径与冻结包精确重核，前文修改/改名/重排/跨卷移动/回收/删除使旧包不可执行。旧无前文包维持原逻辑。

## 作者界面
配置区域可选择前文，显示卷章目录顺序/标题，过滤目标及之后章节；不自动选中、不自动传稿。失效选择可明确移除。未保存更改阻止生成包/采纳，配置回执、跨epoch恢复、同epoch对比重基同原安全逻辑完整包含前文集合。包详情懒展示冻结前文全文与版本/位置、引用片段支持context句柄；可折叠，长窗口可滚动。

既有逐卡人工审阅对象仍为必需设定/大纲等资料。前文是补充上下文，界面明确“前文衔接仍需作者检查，逐项符合不代表系统检查了所有叙事连续性”。不扩张为自动语义检查或全书一致性保证。

## 兼容/校验
JSON写11读1..10，旧格式不得夹带新上下文语义。SQLite无需新表，现有policy/pack记录携带字段；保留旧无歧义handle1/2归档。验证上下文集合与快照严格一致、父链同书/活动、冻结前文严格在冻结目标之前、唯一ID、不等于目标、长度/编码配额、句柄版本与字段匹配。恢复冻结证据不能依赖当前原章仍存在，但冻结自身不能伪造deleted/跨书/乱序身份。新快照与既有source快照若引用同章必须一致，不允许两份相互冲突。恢复继续归档/轮换epoch/暂停策略、替换确认与恢复前留底，当前引用删除不抹去旧证据。

## 验收
中文/emoji/CRLF前文分块及引用；跨卷顺序和相同sort_order稳定ID；跨书/后文/自身/重复/第9项/大章/总包超限拒绝且不半写；修改前文后目标revision不变仍拒绝提案/审阅/采纳；重排删除时拒绝并可修改配置恢复使用；旧configure不清空。JSON11/SQLite有效归档往返与坏证据拒绝；真实JSON/MCP可读context但不能配置或采纳，回执仍有界。React选择、失效移除、dirty、未知回执、恢复与引用显示回归。不声称未执行的原生/浏览器/socket验证。
