# 写作审阅中就地核对伏笔来源
v15 的正文建议显示冻结出现引文，但不能在原面板看已保存来源周边。切到独立伏笔面板需要离开并重选建议；有未保存审阅时原面板禁止关闭。保留现有独立伏笔管理，不把核对变成跨面板跳转，也不默认加载整章。
在已有冻结出现区提供按需只读核对：保持卷章、冻结版本、引文，并通过同书和当前 epoch 的受限桌面只读接口 get_foreshadow_source_window(book, chapter, epoch, start, end) 对照已保存正文。单条 SQLite 作用域 JOIN 返回同一行的卷章元数据与片段；输入跨度最多 4096 个 Unicode 标量，左右固定各至多 80，响应正文原始 UTF-8 合计最多 17,024 字节（不含元数据和 JSON 转义）。10 MiB 原正文体积门限沿用；SQLite 可能内部物化整字段，Rust 借用并校验 UTF-8，不创建完整正文字串，仅复制片段。使用 Rust 标量坐标，正确保留 NUL、CRLF 和 emoji，不用会遇 NUL 截断的 SQLite 文本 substr。修改而引文不变仍视为旧依据；位置变动单列；不可读不猜原因。归档不读现库来源。退出核对、换建议、换库让已发出请求的迟到结果无效，不阻塞审阅，不触发保存、更新依据或采纳。界面不判断文学回收。

复核要求：专用 epoch 读与片段读取均放到 Tauri async command 的阻塞工作线程，Store.try_lock 失败即提示忙，不改共享写入调度。停止是本地放弃显示，不承诺取消后台 SQLite。Windows/native 未验。
