# 墨卷「番茄章稿」实施计划

**基线：**用户提供的 `MoJuanNovelStudio-src-v0.1.1-20261127.zip`，SHA-256 `8c6e66019ff25e1d0111e355f885f191cd9bcefc899eb8315f2409be05afeea2`。  
**目标：**独立功能区一次准备多章，在番茄逐章核对；用两卷六章假稿找出「创建章节」和「填写三栏」分别能节省多少时间。  
**架构：**Rust + SQLite 只读章稿接口、React 独立页面、与生产功能隔离的离线模拟器。已有 TXT 导入/导出、正文编辑和智能体接口不变。

## 边界

- 按当前账号没有官方批量导入设计。只在本地批量准备；不尝试私有接口、不保存凭证、不实施生产浏览器扩展。
- 本轮不访问账号、不处理现有作品、不向真实站点写入任何内容；测试以原创假稿为准。Windows 原生验收仍暂缓。
- 只读正式正文。输入法组字或保存状态不明确时先解决，不输出恢复副本、设定、大纲、审阅记录或 AI 候选稿。
- 进入下一章前由作者核对番茄存稿。手工确认是作者记录，不是平台回执；未确认不推进、不重试、不改同章正文。没有自动存稿、提审、发布或 AI 声明操作。

## 工作项

1. **章稿读取与版本。** 新增 `src-tauri/src/fanqie_packet.rs`、`src-tauri/tests/fanqie_packet.rs`，将仅限桌面主窗的目录、取稿命令接入 `desktop.rs`，在 `api.ts` 暴露。目录只返回活动卷章元数据，按 `sort_order, id` 计算全书序号。读正文时在同一 SQLite 快照重核书库代次、作品、卷章 ID 与名称、章顺序和正文修订，单章最多 10 MiB。先写真实 SQLite 用例：跨作品、回收、标题只改名、调序、修订、旧代次、原样换行与标点。命令不进入 agent/stdio。
2. **独立工作区。** 新增 `src/FanqieWorkspace.tsx`、`src/fanqieQueue.ts`、`src/fanqieTypes.ts`。在左栏加入「番茄章稿」，离开写作区沿用保存检查并阻止组字中切换。选择作品和章节，按本地卷分批绑定番茄卷名和起始号；建议编号可手调，按目标卷检查重复。主区只展示当前项，提供逐字段复制和手选文本。重新读取已保存正文后，作者核对填写和存稿，再手动推进；检测变更则重建队列，不会自动替换版本。首轮队列仅在页面内，不假装可跨重启续传；离开页面会明确告知。测试选章、跨卷、重复号、异步事件、失败和最终确认。
3. **离线对照。** 在 `qa/fanqie/` 提供可直接打开的静态模拟器，硬编码原创六章，不接正式书库或真实站点。A 手动建章和填写三栏；B 手动建章后一键填入；C 一次打开空白编辑器并填入。三组都要手动核对并存模拟草稿。记录耗时、操作数、返工；对照原文，检查非空、错卷、重复操作与中断。以肉眼核对加字段回读，自动化只证明正确性，不替代人的耗时。
4. **验收和交付。** 执行前端完整测试及生产构建、Rust 定向和完整测试（若工具链可用）；本地浏览器或 DOM 组件验证明确分开记录。按 A/B/C 轮换先后，每种六章，从准备当前章计到人工核对正确，单独记录存稿；建议目标为相对 A 中位耗时至少降低 50%，且无错卷、错号、漏章、重章、正文差异。若未实际计时，不宣称达标。交付源码、计划和本地操作说明，不推送或发布。
5. **后置准入，不属于本轮。** 拟议实站单章测试必须另行获准，确认平台允许、打开编辑器不会误建或覆盖，并用作者明确指定的章。保留对照和草稿箱检查；页面变化、登录/风控/提示、身份不符或存稿结果不明即停。未验证前不承诺 C 可上真实站点。
