# 拆章后伏笔来源与审阅验收

目标：贯通现有拆章、伏笔、建议采纳路径，不增加自动迁移或语义判断。

1. 在 `src-tauri/tests/longrange_foreshadow.rs` 复用《苇门背潮》第二章及第二十一章的原创片段，在两个独立文件 SQLite 库创建同样的旧铺设记录、冻结包、书级智能体建议和作者认可。不开拆章的分支应成功采纳并增加恰好一条正文历史。
2. 拆章分支沿 `prepare_chapter_split`（UTF-16 游标）到 `commit_chapter_split`。核对原章/新章 ID、版本、位置和正文拼接；唯一引文完整进入新章，旧历史仍含旧字节。用作品级连接读取旧冻结引文及旧实时记录，证实仍绑定旧章且过期。旧认可不能采纳，也不能重冻同一过期来源；用新幂等键验证旧包不能收新建议，核对零目标正文/历史写。重开数据库后重验。
3. 通过作者现有操作回收旧出现、显式在新章按新 Unicode 标量位置登记；核对新出现 ID、来源章和版本。重冻并验证仅含新出现，在同一候选文本上创建不同提案；直接复用旧认可版本应因尚未完成审阅而失败。显式新审阅再采纳；关闭重开验证旧审阅仍是历史、仅新提案采纳、目标正好增加一条历史。
4. 专项 Rust、相关回归和全量 Rust；在 `docs/ACCEPTANCE.md` 记录复跑路径及证据边界。复核数据均为原创固定样本、模拟人审、真实服务与文件 SQLite；不声称 Windows、真实作家或外部模型验收。
