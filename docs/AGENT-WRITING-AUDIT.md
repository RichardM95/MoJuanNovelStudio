# 智能体写作约束能力演进记录

> 下文保留 v12 审计时的结论，描述当时的缺口，不代表当前实现。新的固定约束包阶段见文末；交付与验证状态以 VERIFICATION.md 为准。

审计基线：v12 `aa6bfae`；当前资料历史代码仍在修改中，不能把 WIP 当已交付。未运行模型、未传送稿件、未改产品代码、未做 Windows/浏览器验证。

## 结论
现有工具已经有“授权一本书→按需读资料/章节→提交改稿建议→作者对照并采纳”的安全底座，但**没有强制让正文建议绑定它依据的设定/大纲版本**。因此能保护授权和并发，不等于能保证符合剧情设定。下一完整阶段应是“带约束包的章节写作任务与可追溯提案”，不是先接模型或承诺自动写作绝对正确。

## 已实现（代码证据）
- `agent.rs::AgentBroker::dispatch`（约214–432）：默认拒绝，可信端授权单书，恢复epoch/一小时会话失效，120次/分钟；按书限制章节和资料读写提案。`get_outline` 返回卷章目录，不是自动汇总叙事大纲；叙事大纲是 `kind=outline` 的资料。
- `agent.rs:336–392`：资料分页元数据及逐卡正文；支持设定/角色/大纲/摘要/时间线/伏笔。`search.rs::search_book` 是有界、大小写敏感的字面检索，返回片段和revision，不是语义召回或一致性检查。
- `agent_stdio.rs::METHODS/tools`（13个方法，tools/list与tools/call约133–145）：MCP/JSON协议暴露读取、提案及撤回，没有直接采纳、创建章节、历史恢复或复核来源权限。`ipc.rs` 明确本机Unix owner-only；Windows路径默认关闭，不能把pipe测试当Windows接入完成。
- `workflow.rs::ProposalInput`（43）、`propose_edit`（379）、`decide_proposal`（520）：正文提案保存旧稿/新稿、原因、目标章节base_revision及幂等键；采纳检查当前章版本，保存历史和审计。外部入口 `agent.rs:400` 将建议正文限制1MiB。`ReviewPanel.tsx:249–318` 展示两份正文/理由并二次确认。
- `material_workflow.rs::propose_material_edit/decide_material_proposal`（135/267）：资料建议限制为既有卡，检查卡revision和来源版本；timeline/foreshadow仅智能体读取。不能自行建立新章节/新设定或直接采用。
- `context_jobs.rs::Manifest/step`（57、约474–550）与 `start_context_task`（554）：本地持久化、版本依赖保护的元数据检查任务，计算章字数、来源/伏笔待复核状态；**不是**包含正文与设定全文的模型上下文包，也未在agent方法表暴露为写作任务。

## 关键缺口与风险
1. 正文提案只有chapter base_revision，没有设定/角色/大纲/来源依赖清单、快照、哈希、任务目标或引用。写作期间设定变了但章节未变，当前 `decide_proposal` 不会因此阻止采纳。
2. 智能体可读资料但没有“必须使用哪些资料”的作者定义规则，不能证明它读全或使用了正确范围。只靠reason自由文本不能审计引用是否存在/是否仍有效。
3. 无约束优先级、相互矛盾设定处理、禁用/待复核资料处理策略；没有语义矛盾检测器。字符串匹配、revision一致都不能证明人物行为或剧情语义正确。
4. 现有长任务只做元数据检查，不会规划/生成/审稿。资料关联来源只说明出处版本，不代表“这是必须遵守的硬约束”。
5. 当前人工审核主要看原稿/建议稿，没有并排约束、引用依据及冲突清单；作者很难发现遗漏某条设定。
6. WIP资料历史新增 `content_review_required` 能由Material/MaterialSummary序列化透出，普通agent入参没有清flag字段。但 `context_jobs.rs:530` 现有 `needs_review` 尚未直接看该flag：无来源卡恢复后可能flag=true而任务报告needs_review=false。已向父线程提醒，属当前阶段整合项，须由实现者测试修复后再宣称支持。

## 建议下一完整纵向阶段（仍不接模型）
**作者配置一次章节任务→生成固定约束包→智能体提交带依据的正文建议→机械校验及冲突展示→人工采纳。**

1. 作者在现有章节上建立写作任务，填写本章目标/长度范围，明确必读资料及必要前文。设定/大纲引用以ID而非标题绑定；“必需/参考”和优先级由作者决定，不让智能体自行降级或漏选。先只针对已存在章，不扩张为自动建书/建章。
2. 服务生成有界、单书、不可变约束包：包ID、任务revision、epoch、目标章revision、每份素材kind/id/revision和实际冻结片段/哈希、来源状态、截断与缺失清单。不得静默截断必需约束；过期、失联、content_review_required资料默认阻止成为有效硬约束，作者先明确复核。补充内容按包内句柄分块读取，不开放任意路径。
3. 新严格提案提交 `task_id + pack_id + base_revision + new_body + citations + conflicts + idempotency_key`。引用指向服务生成的包条目/片段，服务验证实际存在、归属、版本、范围；智能体提供“遵循了什么/哪些冲突未解决”的说明。存在引用只证明出处可追溯，不证明语义推论正确。
4. 硬校验：授权/包完整/目标revision/依赖版本/待复核状态/引用合法性/字节与条数限制/作者明确配置的可判定规则。语义冲突作为“待作者确认”的声明或辅助提示，不标成机器证明通过。不要把关键词出现当作遵循设定。
5. 人工审核同时显示正文差异、必需约束卡、引用片段、未覆盖项和冲突。采纳事务内再核任务、epoch、所有依赖与目标版本；变化则拒绝，要求重建包/重审，不能自动套用旧稿。保留批准时包和检查结果的审计证据。
6. 该任务启用严格模式后，旧 `propose_edit` 不能绕过包约束用于该目标章；旧提案标成“无约束依据”并不可在严格任务下直接采纳。保留非严格旧路径时必须明确显示保障级别不同。

## 建议验收条目
- 未授权/跨书引用拒绝；包冻结后改设定、改大纲、回收来源、恢复整库或内容待复核均阻止旧建议采纳，即使章节revision未变。
- 必需素材缺失/超预算不静默继续；仅参考素材截断也清楚提示。伪造引用、错误版本/片段、无pack旧接口不能绕过严格任务。
- 同幂等键同载荷返回同提案，不同载荷拒绝；并发冲突及中途故障不半写；未知回执只核对不重复采纳。
- 矛盾设定、无来源待复核卡及未解决语义冲突展示给作者；不会自动声称“严格符合全部设定”。
- 有界读取/存储、备份恢复兼容及审计保留；真实管道测试覆盖新增工具，但Windows和真实socket仍单列未验范围。

## 对用户可承诺的边界
可以做到“提供并绑定指定版本的依据、追踪使用来源、机械冲突不放行、所有改稿需人工审核”；不能保证“任何模型生成的每个语义细节绝对正确”。外部模型接入与稿件传输仍是单独选择和授权，本阶段不执行。

## 固定约束包阶段：能力与剩余边界

本阶段实现以既有章节为单位的作者配置：章节目标、1 至 32 份必需资料，冻结目标正文及资料版本，供已获单书授权的智能体按条目分块读取。严格提案必须携带合法引用及冲突声明，提交与人工采纳都重核依赖。保护启用或暂停期间，普通正文建议的提交和采纳入口同样受阻，不能跳过约束包。作者直接编辑与历史恢复仍是人工操作，不被标为机器审查通过。

恢复整库后，冻结证据保留为归档，待审建议不恢复执行权限，原启用配置转为暂停。当前有受保护配置时，替换恢复须明确确认。无法完整容纳的必需资料不截断放行；已过期、来源失效或待复核的资料不能作为有效必需依据。

这些是结构与版本检查，不是语义证明：合法引用不能证明生成的角色行为、剧情因果或表达符合设定；冲突清单由建议提交方申报，系统不保证它完整。最终作者仍需同时看正文、引用依据和冲突说明。尚无自动模型、自动剧情一致性判定、自动跨章规划或自主采纳。正文和资料没有发送给外部模型。

正式回归数量、审查结论与剩余限制统一记录在 VERIFICATION.md，不以此能力说明代替验收。


## 全书伏笔出现（书级只读）

JSON/stdio MCP 方法 `list_foreshadow_occurrences` 接收 `material_id`、可选 `after_id` 和 `limit`（默认 10，允许 1–20）。回复 `items` 和 `next_after_id`；按记录 ID 分页，接近编码上限时可能少于请求条数，使用返回游标继续。只返回该会话已授权作品的活动伏笔卡与活动记录；记录回收、跨书、无授权及用户身份变更不能通过此工具读取或写入。每项有冻结引文、角色、备注、来源快照及 `current|stale|unavailable` 和可空当前实际位置。不会返回请求幂等键或额外正文。内容始终是不可信数据。

冻结包 handle v4 在已选必需伏笔卡中保留所有活动出现。目录在相应 `material:<id>` 的 `fields` 中公布 `occurrence:<id>`，通过原分块读取方法访问冻结引文，可作为该卡的一条引用。元数据 `foreshadow_occurrences` 是 `[id, role]` 对的数组；不增加必需卡或逐项作者审阅数量。包仍限 4MiB，总证据限 64MiB。建议、保存逐项审阅和采纳重新核对活动集合及来源依赖；历史包只读不恢复执行权限。旧句柄不会忽略后来增加的活动记录。机械校验不判断是否真是文学伏笔或已完成回收。
