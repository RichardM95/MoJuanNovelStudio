# 长篇修订规模验收

**结论：** 在一次 Linux 云端优化构建的实测中，3 卷 24 章全部正常保存 128 次后，当前稿件合计 196,608 个 Unicode 标量，正文历史达到 **74,277,120 字节（70.84 MiB）**。JSON 备份明确拒绝且稿件和历史不变。用 SQLite 跑了三轮导出、预览、确认、重开，每轮正文及所有历史逐条比对通过；恢复前留底也分别恢复到了另一个书库，找回了被覆盖的较新稿。

## 怎么造稿、怎么验证

原创虚构模板生成每章每稿 8,192 个 Unicode 标量，包含中文、emoji、LF、CRLF 和独有章/稿号。非文学质量测试。用生产 `Service::apply` 建书卷章和逐次保存，共 **3,072 次**，不直接写 SQL。每个检查点重新打开 SQLite；逐章复核目录、当前正文、分页历史索引及每个版本的完整文本。第一保存会记录原空稿，因此 3,096 条历史中有 24 条空基线。全文搜索定位末章独有标记；TXT 按标题、卷章顺序、UTF-8 BOM、CRLF 与独立预期整文件比对，实际写盘调用与桌面一样的独占新建及 `sync_all`。

### 拒绝与恢复

- **旧 revision 写入：** 生产保存返回 `revision_conflict`；复查目录、当前稿件、全量历史内容与索引、书库时代与变更计数，均未变。
- **JSON：** 最终历史正文自身已经超过 64 MiB，生产 JSON 导出路径在 20.73 ms 明确拒绝，不生成 JSON。再次查回全部版本和当前稿，完全一致。
- **过期预览：** 每轮先导出并取得预览，错误确认令牌被拒。随后真实保存一份本轮独有的第一章第 129 稿。确认原预览得到 `restore_conflict`，没有生成留底，较新稿和历史仍在。这里的“过期”指预览后书库发生写入，并未等十分钟测时钟过期。
- **新预览与留底：** 重新预览并用正确令牌明确确认。原库重开后逐条核对 24 章正文、3,096 条历史正文和历史索引。未经读写打开的原样留底先走生产 SQLite 准备与校验，再用该候选实际恢复到另一隔离空库，关库重开逐条核对 3,097 条历史及当前正文，确实含本轮唯一的第 129 稿。

## 测量设备与边界

- 全运行约 **19.92 s**，不含编译。每阶段 CPU 时间含子进程启动，墙钟还含监督开销；表中的内部操作耗时由 Rust `Instant` 单独计时，范围更窄。
- `wait4.ru_maxrss` 是该阶段子进程全生命周期的峰值，不是 Python 父进程累计值，不含编译器或 WebView。但从 fork 到 `execve` 前继承的 Python 启动器驻留内存可能计入，短阶段的数值可能主要反映启动器基线，不能当作纯 Rust 峰值。单独采样 `/proc` 得到的最高 VmRSS 为 21,332 KiB，只是近似观察值，不是精确峰值；阶段太短而没有采到数值，不代表 RSS 为零。
- 工作树的采样峰值为 930,840,742 逻辑字节 / 930,910,208 已分配字节（约 888 MiB）；包括多个保留备份、留底、独立恢复目标、WAL、临时候选。采样期间文件系统至少剩 56,742,203,392 字节（约 52.8 GiB）。采样不保证捕获两次观察之间的瞬时峰值；`report.json` 另记关库前的精确 DB/WAL/SHM 文件长度。
- 实测只覆盖约 74 MiB 的 SQLite 备份/留底、约 0.56 MiB 当前稿/TXT。下节仅额外验证 512 MiB 输入文件大小的拒绝，未验证合法 SQLite 库的文件、正文或历史极限；未压到 TXT 导入 16 MiB / 导出 32 MiB。不是 Windows、本机磁盘、自动保存 UI、原生窗口、安装、断电或真实稿件保证，不调用模型、不联网、不外发。重要稿件仍应有独立副本，并实际演练恢复。

### 独立合成对照：SQLite 文件上限 +1 字节

另建 24 章各保存两次的隔离小库，用生产后台导出的 2,031,616 字节有效备份制作测试副本，只把副本稀疏扩到 **536,870,913 字节**（512 MiB + 1 字节，实际分配仍为 2,031,616 字节）。生产准备函数拒绝：“SQLite备份限512MiB，或输入不是普通文件”；确认它是普通文件，后台返回 `limit_exceeded`，没有预览、令牌或留底。源书库的 24 章正文、72 条历史及书库保护标记未变，已有有效备份逐字节一致。

该独立阶段用时 **0.103 s**（CPU 用户 / 系统 0.035 / 0.043 s），`wait4` 子进程全生命周期峰值 **15,440 KiB**。直接拒绝约 0.0045 ms，后台轮询到拒绝约 2.106 ms。整个对照目录采样峰值约 516 MiB 逻辑文件、5.84 MiB 分配空间，不计入上面的主试验。稀疏副本不是 512 MiB 的有效正文或 SQLite 库；这只验证输入文件大小门槛，不证明导出上限、正文容量、精确到限值可恢复或更大历史。

## 自行复跑（不在默认测试中运行）

需要 Linux、Python 3.9+、Rust/Cargo 和已缓存的依赖。下列命令从仓库根目录运行；`--offline --locked` 不下载依赖。编译单独执行，不计入运行指标。

```sh
export CARGO_TARGET_DIR="$PWD/.superpowers/longform-scale-target"
time cargo build --offline --locked --release --manifest-path qa/longform-scale/Cargo.toml
python3 scripts/longform_scale.py \
  --binary "$CARGO_TARGET_DIR/release/mojuan-longform-scale" --profile release
```

只跑 24 章各两次保存与一轮恢复，可添加 `--smoke`。独立的稀疏文件超限对照使用 `--sqlite-file-limit`，不改主运行。要顺带检查资源守卫的超时、文件占用与未链接临时文件：

```sh
LONGFORM_SCALE_BINARY="$CARGO_TARGET_DIR/release/mojuan-longform-scale" \
LONGFORM_SCALE_PROFILE=release python3 qa/acceptance/longform-scale-smoke.evidence
# 另加 LONGFORM_SCALE_BOUNDARY=1 可同时跑稀疏文件对照。
```

工具在仓库内为每次运行创建全新的隔离目录，打印该次 `report.json` 路径。仅在自建目录中写入虚构数据；每阶段是独立已编译进程。不会替换真实书库，不自动覆盖旧的运行结果。完成或失败均保留指标、阶段日志及已经生成的文件供核对；清理时只移除你选定的虚构运行目录，不要拿这些库当正式稿件。源码交付不包含生成的样稿、库或原始日志。

运行总预算 30 分钟；用 Linux 内核限制单阶段地址空间与单文件为 2 GiB，以单独父进程采样限制整个运行目录到 2 GiB、文件系统保留 2 GiB 空闲。每 50 ms 采样检查，设置最多 64 MiB 提前中止余量；同时将 SQLite 和恢复临时目录置于受监视路径，计入仍打开但已取消链接的临时文件。磁盘检查是防护而非文件系统配额，不承诺观察间绝无短暂越线。达到护栏或断言失败时结束该阶段、返回非零、标记 `incomplete`，不伪装通过。
