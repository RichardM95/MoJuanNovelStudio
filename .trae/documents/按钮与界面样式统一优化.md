# 墨卷按钮与界面样式统一优化方案

## 1. 目标

解决“按钮没有按钮的感觉”的核心问题：全局 `button` 被重置成无边框、无底色的纯文字，只有 `.primary`、`.danger` 和少数容器按钮有额外样式。目标是在不改变业务逻辑和交互行为的前提下，为全部界面建立统一的控件层次：主操作、次操作、弱操作、文本操作、危险操作、图标按钮，并顺带统一弹窗骨架与表单行的布局节奏。

视觉方向：延续现有墨青 / 米纸国风，普通按钮采用米白底 + 1px 描边 + 轻投影，主按钮实心墨青。

## 3. 按钮设计规范

### 3.1 新增 token（写入 `:root`）

```css
--control-h-sm: 28px;
--control-h: 34px;
--control-h-lg: 38px;
--control-radius: 8px;
--control-border: #d7d2c5;
--control-border-strong: #bcb5a5;
--control-bg: #fffdfa;
--control-bg-hover: #f6f3ea;
--control-bg-active: #efe9dc;
--control-ink: #3d5158;
--control-shadow: 0 1px 1px #1f30360a, 0 2px 5px -2px #1f303616;
--control-shadow-hover: 0 1px 1px #1f30360a, 0 5px 12px -6px #1f303626;
```

### 3.2 层级与外观

| 层级 | 选择器 | 外观 |
| --- | --- | --- |
| 主操作 | `.primary` | 墨青实心 `var(--accent)`，白字，hover `--accent-dark`，active 下压 1px |
| 次操作（默认） | `button` | 米白底 + 1px `--control-border` + `--control-shadow` + 8px 圆角，`min-height: var(--control-h)`，padding `0 14px`，字重 500 |
| 弱操作 | `.ghost`（新增） | 透明底、透明边框、无投影；hover 出现 `--control-bg-hover` + `--line` 描边 |
| 文本操作 | `.link-button`（新增） | 无框无底，主色文字，hover 下划线 |
| 危险实心 | `.danger` | 保持红色实心，hover 加深，active 下压 |
| 危险描边 | `.danger-text`（升级） | 白底/浅红边 + 红字，hover 浅红底 |
| 图标按钮 | `.icon-button`（新增，可选） | 30×30 方形幽灵按钮 |

状态：
- hover：边框加深、底色变浅、投影增强。
- active：`transform: translateY(1px)` + 内阴影。
- focus-visible：保留 2px 墨青 outline，offset 2px。
- disabled：`opacity:.5`、`box-shadow:none`、`background:#f2efe7`、`cursor:not-allowed`。

## 4. 具体改动

### 4.1 `style.css`：替换全局按钮重置并新增控件层（L61-L107 重写）

- 将全局 `button` 从“纯文字重置”改为上面的“次按钮”默认样式。
- 保留 `display:inline-flex; align-items:center; justify-content:center; gap:7px`。
- 删除重复/冲突的 `.primary:hover` 旧值，统一用 token。
- `input/select` 高度与按钮对齐（`min-height: var(--control-h)`，select 可 32px）。
- 新增 `.ghost`、`.link-button`、`.icon-button`、升级后的 `.danger-text`。

### 4.2 必须显式“降级”为扁平的区域（避免误伤）

全局默认改成描边按钮后，以下原本刻意做成无框的区域必须显式恢复，否则会破坏版式：

- `.rail button, .rail-bottom button`：透明底、透明边、无投影；保留现有 hover 与 `.active`。
- `.cover`：`border:0`，保留书封渐变、内阴影与 hover 位移。
- `.chapter-row > button`、`.row-move button`、`.volume-title > button`、`.volume-name`、`.add-chapter`、`.directory-title button`、`.editor-top [aria-label="返回书架"]`：紧凑幽灵按钮（`min-height:0; border-color:transparent; background:transparent; box-shadow:none`）。
- `.chapter-heading`：透明、无框、无投影，hover 仅变主色。
- `.book-actions button`：改为“小号幽灵按钮”（padding 5px 8px，hover 出现浅底 + 细边），让“信息/删除”有可点感但不抢封面。
- `.paper-toolbar button`：小号幽灵按钮；`> button:first-child` 保留危险色 hover。
- `.toasts button`、`.error button`、`.notice button`：小号幽灵按钮。
- `.writing-recovery-links button`：文本操作。
- `.tasks-panel .task-report-item button`：文本操作。
- `.search-results button`：保留卡片式列表（白底、描边、左对齐、hover 抬升），不要变成普通小按钮。
- `.review-tabs button`：标签页样式（透明底、无框），`.active` 用 `--accent-soft`。
- `.materials-panel > nav button`：胶囊标签（透明底、细边透明），`[aria-pressed="true"]` 用 `--accent-soft` + 主色字。
- `.materials-layout > aside button`、`.history-browser .history-version-item`、`.import-chapters li button`、`.replace-chapters li button`：列表行样式（整行左对齐、透明底、hover 浅底、`[aria-pressed="true"]` 浅青底 + 左侧 3px 主色条）。
- `.tasks-panel .task-list-item`：保持列表行，不套按钮外观。

## 5. 假设与决策

- 按用户确认：覆盖全部界面；允许小幅 JSX 改动（仅添加/调整 `className`，不改结构、文案与事件）；采用墨青描边 + 轻投影风格。
- 不引入 CSS 框架、不新增依赖、不做主题切换。
- 不修改任何组件逻辑、测试选择器、aria 标签与按钮文字，确保现有 30+ 个 vitest 用例不受影响。
- 扁平区域（书封、目录树、标签页、列表行）刻意保留无框外观，避免整屏全是描边按钮造成视觉噪音。
- 颜色全部复用现有 `--accent`、`--line`、`--muted` 等变量，新增变量仅限控件层。

## 6. 验证步骤

1. `yarn test`：确认全部 vitest 用例通过（纯样式 + className 改动不应影响行为用例）。
2. `yarn build`：确认 `tsc -b && vite build` 通过。
3. 运行 `yarn tauri dev`，逐屏人工核对：
   - 书架：新增作品（主）/导入TXT/导入作品文件夹（次）/卡片“信息、删除”（小幽灵）。
   - 编辑器：顶部返回、保存、导出；工具条按钮；纸张工具栏；目录树选中与 hover。
   - 导入TXT弹窗（对照截图）：关闭、选择TXT文件、更新预览、导入为新作品、确认导入的层级与对齐；窄窗口下的换行。
   - 导出、拆章、替换、搜索、备份、检查任务、创作资料、改稿与历史、写作约束、伏笔、智能体连接面板：头部关闭按钮、主/次操作、列表行选中态。
4. 检查键盘可达性：Tab 焦点环清晰，Enter/Space 可触发，disabled 状态不误导。
5. 检查 hover / active / focus / disabled 四种状态在浅色纸面背景上的对比度。
