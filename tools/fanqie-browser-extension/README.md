# 墨卷番茄填稿扩展 0.3.0

## 从 Codex 自动存草稿

先在墨卷「智能体连接」配置 Codex 和番茄浏览器扩展，登录番茄作家后台，按扩展提示绑定当前作品的草稿箱和卷。此后可以说“把《书名》第 12 至 14 章存到番茄草稿箱”。扩展在收到指定任务时，逐章查重、创建空白章节、填入并点击「存草稿」，随后从新的草稿箱页面打开该章核对三栏。只有核验成功才会处理下一章。遇到同号异稿、授权或版本变化、无法辨认的页面，会留下原因供核对。墨卷和浏览器需保持运行。[连接与授权步骤](../../docs/AGENT-INTERFACE.md)

自动模式通过当前用户的本机消息主机接收任务。首次启用时，Chrome 或 Edge 会询问是否允许扩展访问番茄站点。适配器仅在番茄作家后台操作，要求能识别绑定的书和卷、草稿总数和编辑字段。请先用指定测试章节验收。隔离 Chromium 测试通过模拟页面验证了空章、两章顺序存稿、草稿箱回读、重复请求、错卷、同号异稿和存稿后回执中断。真实站点页面识别及实际账号存稿仍待验证。

## 手动填稿模式

**一次填一章，作者核对并手动点「存草稿」。** 不创建章节，不点击「存草稿」「下一步」「发布」，不处理 AI 声明，也不绕过任何提示。首次只在平台允许的情况下，用你有权测试的空白章节和自选测试稿试用。虽然扩展不点保存，番茄编辑器可能自行保存输入，别在不打算改动的作品里试。

## 操作

1. 解压。Chrome 打开 `chrome://extensions`，Edge 打开 `edge://extensions`。打开开发人员模式，点「加载解压缩的扩展」，选择本目录的 `extension`。不要安装来历不明的同名扩展。
2. 用本包的墨卷源码构建后，在左栏「番茄章稿」核对**番茄目标作品**、卷名和章号，读出已保存正文，点「复制本章给浏览器扩展」。在番茄先手动打开这部作品的一章空白编辑器。
3. 点扩展图标，在弹窗粘贴整份章稿，点「核对目标」和「交给当前网页」。首次按网页面板提示点显示书和卷的位置，再依次点章号、标题、正文。这里的点选只用于识别，不会触发原网页按钮。识别只保留在当前页面，同一页字段不变可以复用；页面重载或换页后可能需要再选。
4. 在网页面板点「一键填三栏」。出现「三栏已核对」后，你仍需自行检查并按番茄的「存草稿」。回墨卷后，只有你确认存稿才点下一章。若页面未报告存稿或显示异常，先检查草稿箱，不要盲目重新填。

若提示不识别，核对打开的是原始番茄作家编辑页、页面上只有一个可见「存草稿」。新版只识别 `https://fanqienovel.com/main/writer/` 下的网址，章节页或字段变化时会停，不会尝试在其他网站上填。手动模式使用当前页权限，你需要自行登录和粘贴。手动填稿不会启动自动任务。

## 验证边界

在 Chromium 中对**拦截替换为假页面**的番茄地址验收了数字、标题、富文本正文的读取，实际没有联系番茄网站。测试覆盖：空行和标点逐字读回、错卷不填、非空不覆盖、页面中途改写即停、填写没有触发保存、最后鼠标手动点保存才记录。未验证真实站点的编辑器内部状态、自动保存、Windows/Edge 原生扩展安装或实际存稿。浏览器表单仅将 CR/LF 规范化为 LF；若其他内容被网站转换，则报出需人工核对。报错后不要当作已存草稿。

无账号模拟：从本目录运行 `py -m http.server 4173 --bind 127.0.0.1`（也可用 `python`），打开 `http://127.0.0.1:4173/mock/index.html`，使用扩展「载入假稿」。这个模拟入口有独立测试，不访问番茄。扩展使用 [Chrome activeTab](https://developer.chrome.com/docs/extensions/develop/concepts/activeTab) 和 [scripting](https://developer.chrome.com/docs/extensions/reference/api/scripting)。
