# 墨卷逐章填表脚本验证

先做只在本地验收页运行的 Chrome / Edge 扩展。作者把单章数据粘贴到扩展，核对目标，点击「填入本章」后，由脚本填写章号、标题、正文，逐项回读。草稿/提审为单独的人工操作，当前版本不执行。严格按复现结果决定下一步如何识别番茄真实编辑器，而不是从截图猜测字段。

1. 用 Node 测试先锁定数据格式、跨页面、错书卷、已有正文、截断、重复点击和竞态。
2. 独立的 Manifest V3 扩展只在当前标签页执行，没有 Cookie、剪贴板读取、持久存储或网络请求权限。限制入口为 127.0.0.1:4173 的固定模拟页。
3. 用 Chromium 检查填写后原文相同、未点击提交；核对前后分别读取页面；确保先只用假稿。
4. 如果要启用真实站点，先核对编辑页实际字段和编辑器保存行为，并明确「确认提交」到底是存草稿还是提审，之后再确认具体实站实验范围。

## 0.2：作者确认存草稿

- 墨卷提供单章包，内含作者指定的番茄作品名、目标卷、章号、标题、已保存正文；不扩大智能体能力。
- MV3 扩展在作者手动打开的编辑页做字段标定，只读检查唯一可见「存草稿」和目标头部，不点击它们。填写前、每栏填写后和结束复查当前页、目标与内容；失败则不推进、不重试。
- Chrome 中用本地拦截的合成番茄页验证真实渲染；不将假页通过解释为现网适配验证。实站验收和原生 Windows 验收仍未进行。
