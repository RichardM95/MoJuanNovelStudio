# 墨卷 · 离线小说写作（0.1.0 源码预览版）

当前版本提供源码与本地 Windows 构建。安装、升级和卸载需通过安装包单独验收。

> 当前版本支持混合资料整理、已有作品资料卡复核和按章检索。外部写作智能体可经 Windows 本机 MCP 接口访问作者授权的作品。

## 已实现
- 书架：新增作品、修改书名/作者、搜索、移入回收站、恢复。
- 作品：卷章新增、改名、上下排序、章节跨卷移动、可恢复删除。卷章编号按目录自动生成，章节全书连续编号。
- 回收站：统一管理作品、卷、章节。子项须先恢复父项。永久删除须输入名称确认，会级联移除所有下级内容，不删除独立备份。
- 纯文本写作：800ms 自动保存、Ctrl+S、离开前保存、中文输入法组合期不触发自动保存；保存失败保留当前编辑内容并阻止切换。
- SQLite 本地持久化、事务与 revision 检查、单实例入口；不使用浏览器 localStorage 存稿。
- 整书 UTF-8 / CRLF TXT 导出；整库 JSON 备份恢复（含回收站）。恢复前另存经校验的 SQLite 一致性快照，导入校验与替换在事务内完成。

## 章节历史与重要版本
在作品中打开“改稿与历史”→“章节历史”。历史索引每页50条，按新到旧排列；点击一个版本，才显示它与当前稿件的正文。

- 为已有历史填写名称，例如“第一稿定稿”，可筛选仅显示已命名版本。名称修改不改正文、不创建新的正文快照；清空名称也不会删除历史。
- 打开面板前先保存当前正文；新建且尚未编辑的空章节可能没有历史。每次正文保存保留快照的既有策略不变。
- 命名有独立版本冲突保护，失败保留名称草稿；切换、刷新和关闭前请保存或明确取消编辑。
- 恢复选中版本须二次确认，并校验当前章节版本和书库时代；成功后生成新版本，不覆盖旧历史。名称标记是查找工具，不能替代独立备份。
- JSON v13 保存版本名称、资料内容历史、逐项作者审阅、冻结前文、伏笔出现及建议审计，兼容恢复 v1–v12；旧备份未保存的名称不会补造。完整历史仍占用磁盘，64MiB JSON备份上限没有提高，不自动删除历史。

## 本地检查任务
作品工具栏的“检查任务”会先保存当前正文。检查按章节统计非空白 Unicode 字符数，并整理资料来源待复核、失联和未回收伏笔；不是剧情质量分析，不调用模型、不修改正文、不外发稿件。

- 后台逐项处理，进度仅计算已提交结果；关闭面板不会取消。取消在当前项完成后生效。
- 重开应用不会自动继续旧任务。只有输入版本和完整目录仍一致时才能手动继续检查点；输入改变须重新检查，新任务不会覆盖旧报告。
- 报告只是检查时的历史快照；部分结果不代表全书结论。点击条目可定位到当前章节或资料，内容可能已与报告不同。
- 每任务最多5000个活动章节/资料，输入元数据快照4MiB；最多8个活动任务、100条保留记录，任务元数据与结果共64MiB。达到额度明确拒绝，不自动删除历史。
- JSON v13 备份只含正式书库数据，不含任务运行记录；恢复会清除当前任务并更换输入时代。恢复前经校验的SQLite快照包含当时任务记录。
- 后台异常会停止检查并提示重开应用，不自动反复重试数据库写入。当前没有任务历史清理入口；达到保留上限后不能再新建任务。

## 创作资料
在作品内点击“创作资料”。按设定、角色、大纲分组，点击单张卡片查看和编辑。设定支持简介、题材、世界观、风格与规则；角色支持身份、性格、外貌、目标、关系与状态；大纲可关联全书或同作品内卷/章。资料不是编写正文的前置要求。

资料采用明确的“保存资料”按钮或 Ctrl+S；未保存或写入失败时阻止切卡和关闭，保留草稿。资料内容历史可恢复标题和字段，关联/剧情状态不回退；删除可以从资料回收站恢复。删除关联卷章不会删除资料文字；永久删除作品会同时清除其资料。

单卡内容限256KiB、每书最多1000卡（含回收站）、资料总内容限32MiB，达到限制会拒绝写入并保留旧数据，不自动清理。智能体可在单书授权范围内搜索/读取，并对已有资料提交标题、字段及既有来源版本的更新建议；不能直接修改、恢复、创建或删除资料，必须在界面对比并人工采纳。未接入模型。

### 来源、摘要与建议审核
- 摘要需人工选择来源章节。其他资料也可记录来源，与大纲的关联范围相互独立。
- 章节正文更新后，来源版本不同的资料显示“待复核”；源章节回收/删除显示“来源不可用”，资料文字保留。版本未变不代表内容准确，需作者核对。
- 编辑资料不会自动把来源变为最新；核对后点击“按当前章节版本复核”并保存。
- “书内搜索”匹配当前作品活动章节与资料的字面关键词，返回有限片段，点结果打开。大小写敏感，非语义/向量检索，最多展示30项；缩小关键词继续查找。
- “待审资料提案”显示提交时原值与建议值。采纳需要二次确认，并同时检查资料和来源版本；过期建议必须重新提交，拒绝不改资料。只更新已有卡，不新增或删除。
- 资料历史仅恢复标题和字段，不回滚关联或剧情状态。JSON备份保留正式资料及内容历史但不保留提案审核记录；恢复前SQLite快照保留当时完整库。旧v1-v3没有资料；v4资料无来源记录，显示“未记录来源”。

### 时间线与伏笔
- 时间线记录事件、故事顺序和时间标签，区分计划与已发生。故事顺序是作者填写的0..1,000,000,000整数，不等同于章节编号；同序按ID稳定排列。
- 伏笔区分待铺设、已铺设、已回收、已放弃。填写铺设内容与回收说明，分别选择对应章节；已回收须有回收说明及两组可核验来源。
- 时间线/伏笔列表只显示简短索引，点击单卡编辑。伏笔可按状态筛选，筛选时也保护未保存稿件。
- 章节修改后提示来源待复核；章节删除后保留剧情文字及失联标识，不擅自改变剧情状态。两组来源需要分别核对后明确更新版本。
- 两类记录使用同一资料回收站与版本冲突保护。智能体只能按书读取/检索这两类卡片，不能用通用资料提案修改卡片；伏笔的出现建议另在全书伏笔中审阅。

### 全书伏笔与章节出现
- 在作品工具栏打开“全书伏笔”。总览跨卷、跨章，可按作者状态或待复核筛选。选卡后查看它的出现；“新增伏笔卡”或“编辑主要埋设、回收与作者状态”复用创作资料的编辑规则。
- 从已保存正文框选原文，标为铺设、提示或回收片段，可写备注。记录保留准确引文、正文版本和原目录位置。正文、标题、卷身份或目录顺序变化后提示待复核；来源回收或删除时在独立区域显示冻结位置及引文。角色不改变卡片的作者状态。
- 原引文不能覆盖。若要纠正，可回收原记录并新建；恢复时保留原片段和原版本。打开全书伏笔和跳转都会先保存当前稿件，保存失败不跳转。写入回执不明时先读取核对，只有明确操作才会使用原请求键重试新增。
- 引文最多 4096 UTF-8 字节、备注 1024 字节、单条编码最多 32KiB；每卡 32 条、全库 10000 条及 32MiB，含回收记录。单章读取先检查 10MiB，不自动截断或清理；目录只读元数据。
- JSON v13 和 SQLite 快照保存回收中的出现及冻结写作依据。旧备份没有多次出现记录，迁移为空；标记为新版却缺少出现记录表的 SQLite 会拒绝恢复，不会被视为旧库。旧库主来源与作者状态不变。来源删除不抹掉历史引文；明确永久删除整个作品仍按原书库规则删除该作品的资料和写作证据。
- 选择伏笔卡为写作必需资料时，新包冻结完整的活动出现记录。来源待复核、失联或集合变化会阻止使用旧包；已经存好的引用仍可阅读。获单书授权的智能体可分页读活动正式出现并提交独立建议，但不能登记正式出现或替作者判断。

### 审阅智能体的出现建议
1. 先保存正文，再进入“全书伏笔 → 出现建议”。队列显示本书待审数；从活动伏笔卡也可打开该卡建议历史，查看撤回、拒绝、采纳和恢复后的归档证据。
2. 打开建议，对照冻结的卷章位置、正文版本、精确引文、建议角色/备注/理由及已有正式出现。建议可能与已有记录同片段，不自动合并。“审阅后采纳 → 确认并登记出现”只登记这一条，正文和作者状态不变；也可拒绝。
3. 正文版本、当前目录位置或卡片版本变化、来源回收/删除或卡片待复核时不能采纳，仍可拒绝。采纳会递增该卡版本，随即使该卡其他旧建议及受影响依赖包失效；需要按新版本重新提交，不会自动寻找相同句子。只比较当前目录与冻结位置，无法识别已经完全撤销的纯目录变化。
4. 回执异常时只读核对建议及正式记录，不重复提交决定。如果核对迟迟不返回，可点击“停止等待核对”再退出。这只停止前端等待，不会撤销原决定或证明写入失败。已收到的终态证据会保留，仍须核实书库未更换才能确认结果。本次应用运行内重开仍可核对该条，不影响审阅其他建议。采纳或拒绝的实际提交尚未返回时，原有关闭保护不变。整库恢复轮换书库代际；旧建议与终态证据归档，不能执行。来源删除不删除建议引文；永久删除归属作品则一并清理。JSON v13 与 SQLite 新代际均保存建议历史；v1–v12 导入没有这部分记录。
5. 建议单独计限：引文 4096、备注 1024、理由 2048 UTF-8 字节；单条记录和载荷 64KiB，每卡 20 条、全库 100 条可待审，全库最多 1000 条留存、32MiB 已编码载荷。拒绝/撤回不释放累计空间；不自动清理。正式出现原限额不变。

## Windows 构建
安装 Node.js 22 LTS、Rust stable MSVC、Visual Studio Build Tools 的“使用 C++ 的桌面开发”及 Windows SDK，确保 WebView2 Runtime 可用。
官方前置条件：https://v2.tauri.app/start/prerequisites/

在 PowerShell 解压源码目录后：
```powershell
./scripts/build-windows.ps1
```
开发启动：`npm ci` 后 `npm run tauri -- dev --features desktop`。
使用脚本完成打包后，可在 `src-tauri/target/release/bundle/nsis/` 找到安装器。仓库包含手动触发的 Windows CI 配方。

## 测试
```sh
npm ci
npm test
npm run build
cargo test --manifest-path src-tauri/Cargo.toml
```

## 数据与边界
- 默认书库位于 Tauri 应用数据目录 `com.mojuan.writer` 内的 `library.db`，Windows 通常在 `%APPDATA%` 下；恢复前快照在同目录 `recovery`。程序不写源码目录或其他项目数据。
- 运行期间 SQLite 有 WAL 辅助文件。请用“备份书库”导出，不要只复制运行中的 `.db` 文件。
- 新 JSON 备份版本为 13（含章节历史、历史名称、资料内容历史、待复核标记、来源与剧情跟踪字段、伏笔出现和建议审计、冻结依据与逐项作者审阅），恢复兼容旧版本 1–12，旧 SQLite 库自动补列迁移。恢复父项不会自动恢复之前单独删除的子项。
- TXT 导出不是可完整恢复的备份，SQLite/JSON 备份才保留结构/回收站。恢复替换整个书库，不是合并；取消不改变稿件。
- 为保护旧文件，导出/备份**不覆盖已有路径**，请选择新文件名。即使系统保存窗口确认覆盖，应用仍拒绝，提示另选名称。
- 程序异常断电时，最后约 800ms 尚未落盘的输入仍可能丢失。保存状态表示当前已完成的数据库提交，不等于异地备份。
- 单章正文上限 10MiB，JSON恢复文件上限 64MiB；历史快照会增加备份体积，超过限额将拒绝JSON导出而保留原库；每次保存后仍刷新整库；[长篇修订规模验收](docs/LONGFORM_SCALE.md)记录了 24 章持续修改和恢复的实测，不能外推到超大书库。不支持云同步或富文本；TXT分章采用可核查标题规则，不是语义识别。
- 恢复前 `.sqlite` 快照不会自动清理；当前已支持 SQLite/JSON 图形化两步恢复，边界见 docs/AGENT-STAGE.md。应用目录卸载保留行为与 Windows 实机数据恢复仍待验收。

## 大书库备份与恢复
“备份书库”和“恢复备份”打开同一面板。推荐 SQLite 备份（文件上限512MiB）；JSON为兼容格式，仍限64MiB。选择备份后先校验并显示包含回收项的统计，确认替换整个书库后才执行。预览后书库有任何写入会使候选失效，需要重新校验。

恢复前必须生成并校验当前库的留底快照，再在原数据库事务内恢复，失败回滚。留底不受512MiB限制，成功后显示路径；不自动清理。需为候选、留底与事务预留额外空间。SQLite仅接受当前已知墨卷结构的独立文件，拒绝带有效WAL的运行中库；已知旧 SQLite 缺伏笔出现表时以空表迁移；缺资料历史表和复核列时可自动补基线，更旧版本请使用 JSON 备份。恢复保留作品、目录、正文、版本名称、资料和历史，包括伏笔出现建议及其决定、冻结写作证据。备份中的出现建议只归档供查看，不恢复待审执行权限；任务及普通正文、资料修改提案和相关操作审计不从备份恢复，旧授权失效。

状态查询久久不返回时，可点“停止本次状态等待”，再点“刷新当前任务”或“刷新作业状态”。这只停止界面等待，不取消后台作业，不代表作业失败，也不会重新提交恢复。结果未确认时仍不能关闭面板、开始新任务或提交恢复；确认没有任务或已有终态后可回到写作。

备份任务可查看进度、申请取消；真正提交后不能取消。候选有效期10分钟，重启后需重新选择。超过上限明确拒绝，不删除原库。该功能已在Linux隔离数据及浏览器虚构界面验证，Windows原生运行尚未验收。

## 作品正文批量替换
打开作品后选择“批量替换”。先保存当前草稿，输入查找词和替换词，预览逐章命中；点击一章可查看完整前后正文，再二次确认一次提交全部修改。只处理当前作品的活动章节正文，不改标题、资料或回收项，不支持正则。空替换可删除词，空搜索或相同词拒绝。

原稿保留在章节历史，可逐章恢复；目前没有整批一键撤销。预览后新增、改稿、移动或回收章节会使整次确认失败，需要重新预览。数据库写入中途失败会整体回滚。若提交结果未知或已成功但读取失败，界面只允许重新读取核对，不自动再次替换。

容量限制：查找词256 UTF-8字节，替换词1024字节；全书活动正文扫描64MiB/100000章；单次命中最多500章/100000处；候选前后正文合计32MiB，单章结果10MiB。超限明确拒绝，不执行部分替换，不删除原稿。候选10分钟有效，关闭或重启后需重新预览。本功能不向外部智能体开放。

## TXT导入为新作品
书架选择“导入TXT”，先选“按标题分章”或“全文单章”，再选本机文件。支持UTF-8及开头BOM，文件最多16MiB；GBK、UTF-16、非法UTF-8或含NUL的文件明确拒绝，不做有损猜测。原文件不会修改。

预览可改书名、作者、分章模式，然后重新预览。按标题模式保守识别独立的“第…卷 / 第…章”行（标题后缀用空白分隔），标题行转为卷章名称；其余正文、空白及CRLF/LF/CR换行原样保留，标题前文字归入前言。点击章节查看正文，核对后再确认创建。不能确定识别结果时可选全文单章，保留全部非BOM内容。单章仍限10MiB，因此10–16MiB源必须能合理分章，否则整次拒绝，不截断。

导入始终创建独立新作品，即使同名也不会覆盖旧书。最多200卷/2000章，单章10MiB；全库树记录及历史记录各100000上限。候选10分钟有效，取消/重启需重新选择。确认失败事务回滚，成功保留初始章节历史；提交结果未知先重新读取书架核对，不自动再创建。此阶段不含合并导入、编码转换、智能识别书名作者或预览内逐章重排；可在导入后用编辑器整理。

### 从作品文件夹导入正文和资料

在书架选择「导入作品文件夹」。默认按内容整理目录顶层的 UTF-8 TXT 和 Markdown，同一份文件可以有正文、设定、角色和章纲。工作站建议一份正文，并保留其他稿件供复核。可手动指定正文候选。单份 TXT 最多 16 MiB，Markdown 最多 256 KiB，自动整理累计最多 32 MiB。

目录导入支持「第一卷：卷名」和紧跟排版分隔线的「--第十二章 标题」。卷章预览列出原章号、源行号、缺号和重号。默认排除预览列出的边界分隔线，正文内部的段落和换行保留。

卷章标题、人物角色标注和明确的设定小节可整理成资料卡。多份细纲可一起识别，同章多个条目逐条呈现，作者可以对照原文、选择关联并勾选入库。卡片记录来源文件和行号。原文和未识别的笔记可在「创作资料 → 来源文档」查看。

确认后一次写入新作品、卷章、初始版本和资料卡。预览有效期为 10 分钟。回执异常时可核对书架中的本次作品，资料和关联随书库备份恢复。

对于已经导入的作品，进入「创作资料 → 整理已有资料」，查看从来源文档提取的条目，再采纳所选项。内容重复时复用现有资料卡。
来自同一文件且能唯一对应资料卡的变化会显示原有内容供复核。确认后更新该卡，修改可在资料历史中查看。

### 按章检索与智能体连接

Windows 桌面在作品内提供「智能体连接」。作者可逐个授权连接访问当前作品。外部智能体可以按目标章检索前文和资料，查看精确原文、所属类型、修订版本及文件出处。续写建议继续使用冻结依据包和人工审阅。连接步骤见 [本机智能体接口](docs/AGENT-INTERFACE.md)。

### 定向TXT导出
在作品内点击“导出 TXT”，可选择全书、单卷或单章，设置书名作者、卷章标题、LF/CRLF和UTF-8 BOM后生成预览。未保存正文会先保存，保存失败则不会打开导出。

预览显示实际字节数及前4000个Unicode字符（超出会注明），保存使用同一份冻结文本，10分钟内有效。书库后续改变不改变这次预览；如需最新内容请重新预览。选定范围内卷章从1编号，换行规范化但不裁剪正文。输出最多32MiB，单章最多10MiB，超限可缩小范围；仅新建文件，不覆盖同名文件。取消选择位置可继续使用预览，写入失败或结果未确认需核对文件后重新预览，不会自动重试写入。当前不支持GBK、DOCX或模板导出。

Windows原生保存对话框与EXE验证继续暂停。浏览器预览为虚构数据演示，不写入真实文件。

### 按光标安全拆章
在正文中放置单个光标，点击“拆分章节”。工具先保存当前稿件，再预览原章前半和新章后半；输入新章名并核对后确认。文字选区、输入法组合中、正文首尾或非法Unicode/CRLF中间位置不可拆分。原始换行及文字不裁剪，未编辑的CRLF/CR正文也会正确映射光标。

原章保留ID与名称，新章紧随其后。拆前完整正文保留在原章历史；失败时正文、目录与历史整体回滚。原有资料关联留在原章，新章不继承；原章摘要和来源标为过期，旧正文改稿建议不能直接采纳，请人工复核。恢复原章旧历史不会移除新章，本阶段没有结构一键撤销或合并。

单章最多10MiB，当前卷目录ID/标题总量最多16MiB，树和历史各最多100000条。预览10分钟有效，正文或目录发生并发变动需重新预览；未知提交结果只重新读取核对，不自动再次拆分。


### 创作资料内容历史与关联复核
在资料编辑器保存或取消未保存内容后打开“内容历史”，按页浏览索引，点一个版本才读取标题/字段。确认恢复只恢复文字，不回滚当前关联章节、来源版本、故事位置或剧情状态；若旧文字不满足当前状态要求会拒绝。恢复生成新版本，恢复前内容仍可查看。

恢复后必须显示“内容已恢复，关联待人工复核”，普通保存及智能体建议不能清除。有来源或回收来源时不会显示为当前有效；作者核对并明确复核时还要检查来源版本确为当前，不满足则先更新来源。无来源卡也需要明确复核。复核仅确认作者动作和版本，不代表自动证明文字符合设定。

升级时为已有资料（含回收）保存当前内容基线，不虚构过去历史。资料历史最多100000条、累计256MiB，超限拒绝新写入，不自动清理。旧库升级超限会保留原库并拒绝升级，可用旧版先导出备份。JSON v13 保存资料历史和待复核标记；旧JSON/前一版SQLite恢复时补基线。历史会增加备份体积，JSON超过64MiB请使用SQLite备份。

### 智能体写作保障的当前边界
当前支持按书授权读取、提交建议、人工采纳，不等于保证符合全部设定。启用“写作约束”的章节，严格建议绑定作者冻结的必需资料和明确选择的前文，并校验引用、依赖变化和人工审核；普通未配置章节不享有这些保障。机械校验不能证明语义绝对正确，未连接外部模型或发送稿件。详见 docs/AGENT-WRITING-AUDIT.md。


### 带依据的智能体写作
1. 在已有章节打开“写作约束”，填写目标，选择1–32张必需设定/角色/大纲等卡，可另选0–8章前文，再保存配置。可选章节只来自本书目标章以前的实际卷章目录，不按标题中的数字推断。输入正文会先保存；当前来源失效或内容待复核须先处理。
2. 作者生成冻结依据包，可查看必需卡、目标稿件和所选前文的完整冻结正文、版本及目录位置。包最多4MiB、有效30分钟；目标及每章前文正文分别最多1MiB。任何内容超限都会拒绝，不截断。前文选择目录仅加载元数据，限16MiB，不预读全文。不自动连接任何模型。
3. 已获单书授权的智能体可读取包目录及分块内容，提交引用和自报冲突的严格建议；不能选择降低必需约束、配置/停用保护或自行采纳。
4. 作者在面板查看冻结原稿、建议新稿和各卡引用，分别标记“未审阅”“符合”“有疑问”或“有冲突”，可留备注并保存未完成的审阅。只有所有必需资料都已明确标记并保存为“符合”，才能发起采纳确认；智能体自报的冲突仍须另行确认。
5. 采纳绑定作者看到的已保存审阅版本。提交建议、保存审阅和采纳都重新核对稿件、所选前文、资料、来源、父链和配置。前文修改、改名、重排、跨卷移动或删除都会阻止使用旧包；作者可移除不可用前文并重新冻结，不会删除旧证据。保存回执不明确时先重新读取核对，不会自动再写一次。同一书库若已有较新配置，先对照当前保存内容，之后才能选择保留旧草稿并另行确认保存；整库恢复后不会把旧书库草稿带入。
6. 正文采纳或拒绝只提交一次。面板用独立书库时代与完整提案核对决定，不把列表状态当回执。同版本正文须逐字匹配；若后来已有新版，只提示曾采纳，不会把建议稿盖到作者的新版或未保存稿上。核对挂起可点“停止等待核对”再离开，**不是取消写入**。本次运行内可从原章或“待核对的正文决定”回来，只读核对同一建议；上限为 32 条、32 MiB，超限不提交新决定。全局只读核对不会保存或替换当前编辑器的稿件。决定独立核实后释放正文占额，保留轻量终态以阻止陈旧列表重发；旧库待核对证据仅供查看，可明确清理。退出应用不保存这份临时记录。

启用或暂停约束时，普通无依据建议不能提交或采纳。作者明确停用后才允许普通建议；修改配置会取消本章现存待审建议，不复活旧稿。作者直接编辑、历史恢复仍可用但不是经约束审核的生成结果，拆出的新章也不会继承配置。

包与严格建议各最多1000条、合计64MiB证据，不自动清理；新稿最多1MiB，引用128、冲突32、附注64KiB，编码和传输上限可能更早触发。逐项作者备注每项最多4096 UTF-8字节，整份已编码审阅最多64KiB，计入同一证据额度。JSON v13 和 SQLite 备份保留配置、冻结依据和作者审阅；恢复时旧建议归档不可再执行，启用配置变暂停，旧包失效。旧版已采纳建议原样保留，显示“旧版未记录逐项审阅”，不会补造作者结论。当前有保护配置时整库恢复还须明确确认替换这些配置。

前文是补充上下文，不增加必需引用或逐卡审阅对象。作者应在采纳前核对模型建议中的引用、设定与叙事衔接。
